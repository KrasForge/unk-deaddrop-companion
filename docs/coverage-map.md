# Evidence coverage map

This map records which investigation material became a rule, which material stays an analytic finding, and why. It covers the twelve-part series and the relevant ClickFix, VSIX, Overlord, repository-lure, infrastructure, and ECHOES records reviewed for this ruleset. Related campaign copies are treated as evidence for reusable code and behavior only; a shared marker does not collapse the investigations into one actor. The companion repository contains the signatures and inert fixtures, not the source case files or collected payloads.

All retained rules are experimental YARA file-content signatures. They compile, pass inert boundary fixtures, and matched saved case artifacts. The local software baseline produced no hits. The wallet rule's earlier prose collision is blocked by its current ELF-header requirement, though broader false-positive rates remain unmeasured.

Actual-artifact and local-baseline scan scope and results are recorded in the [validation report](actual-artifact-validation.md). The two workspace-configuration signatures were removed because the raw target files are absent. Event rules were removed because authentic endpoint logs are absent.

## Material deliberately excluded from public rules

- Live or historical authentication tokens, private API credentials, and endpoint secrets.
- Victim-target databases, personal addresses, private messages, and operator identity leads.
- Bare IP addresses, parked domains, expired domains, and shared-host observations as durable indicators.
- Generic `runOn: folderOpen`, Electron, PowerShell, screen-capture, WASM, or Overlord markers without the recovered conjunctions.
- The ECHOES private-repository token and unretrieved final-stage behavior.
- Claims based on retracted domain, hosting, or attribution pivots.
- Private or victim-owned repository names, personal handles, account histories, unreleased case notes, and ownership judgments. Recovered code and behavior may inform a generic signature without carrying those identities into this repository.

## Review priority

1. Expand the benign corpus with representative developer repositories, IDE installations, browser forensic utilities, and ordinary Overlord builds; review every match before enabling alerts.
2. Retain original task and settings files only if redistribution rights permit, then assess whether a repository-file signature is useful.
3. If authentic endpoint logs become available, validate process and file-event detections against them before publishing event rules.
4. Keep infrastructure indicators in a dated, provenance-aware feed if they are needed operationally; do not fold them into these structural signatures.
